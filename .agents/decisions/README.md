# Architecture Decisions

Store architecture decision records (ADRs) here using sequential names such as `0001-typed-transport-boundary.md`.

Each record should include:

- status (`proposed`, `accepted`, `superseded`, or `rejected`);
- context;
- decision;
- consequences;
- date and superseding record when applicable.

Decision records explain why a consequential choice was made; they should not duplicate implementation documentation.
